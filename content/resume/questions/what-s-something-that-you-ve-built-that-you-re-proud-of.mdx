title: What's something that you've built that you're proud of?
order: 2
answer: |-
  One project I’m especially proud of is the personal hybrid-cloud infrastructure I have been building and evolving since high school, now organized under trance-0.com. It started from a practical frustration: I liked the convenience of Apple’s ecosystem, but after moving more of my workflow across Linux and Windows, I realized how expensive ecosystem lock-in becomes. Files, photos, passwords, code, notes, compute access, and media libraries should not depend on one vendor being the only viable choice.

  So I built my own open-source-based infrastructure layer for daily life and research. It includes a home NAS, containerized services, reverse-proxied public endpoints, Nextcloud for cross-platform file sync, Immich as an iCloud Photos replacement, Bitwarden for password management, Gitea for private Git hosting, a personal blog, media services, AI/dev tooling, and remote compute access including DGX-related services. The DNS records show a broad service map across file sync, Git, media, password management, AI tools, deployment experiments, status pages, and remote access endpoints under the same domain.

  What makes me proud is not just that it works, but that it reflects a principle: infrastructure should be portable, inspectable, and replaceable. I learned networking, Docker, reverse proxies, DNS, backups, security boundaries, and operational maintenance by solving real problems for myself. Recently, AI coding agents such as Codex, Claude Code, OpenClaw, Hermes-style agents, and other developer tools have helped me iterate faster, but the architecture and motivation remain mine: build systems that reduce dependency, preserve ownership, and make open-source alternatives usable in daily life.

  Additional details

  The project is less a single app than a living personal cloud platform. I use it to replace or augment many proprietary services that people usually accept by default. For storage and sync, I use Nextcloud hosted on my own server instead of relying only on iCloud Drive or Google Drive. For photos and media backup, I use Immich, which gives me more ownership over my photo library while preserving the convenience of automatic sync. For secrets, I run a Bitwarden-compatible password manager. For code, I operate Gitea so that private or sensitive repositories do not have to live entirely on GitHub.

  The system also includes service-management and experimentation layers. I run most components in containers, expose them through reverse proxies, and manage service routing through DNS records. The domain includes endpoints for services such as nextcloud, immich, bitwarden, git, jellyfin, portainer, status, vllm, ollama, dgx, nas, and other experiments, which reflects both practical use and continuous prototyping.

  A major lesson from the project was that reliability is not only about writing code. It required thinking about upload limits, Cloudflare proxy behavior, private versus public exposure, SSH access, container isolation, backups, sensitive data, and how to recover when one piece fails. For example, some endpoints are intentionally not proxied through Cloudflare because large file uploads or certain protocols are more reliable when routed directly.

  I’m proud of this project because it combines engineering judgment with personal values. It is useful every day, it keeps evolving, and it taught me to evaluate software not only by whether it works, but by who controls the data, how hard it is to migrate, and whether the system can survive changes in vendors, platforms, or tools.
